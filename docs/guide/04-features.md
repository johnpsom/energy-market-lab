# Κεφάλαιο 4: Feature engineering

## Το πρόβλημα
Ένα μοντέλο μηχανικής μάθησης δεν «καταλαβαίνει» αγορές ενέργειας. Βλέπει αριθμούς. Αν του
δώσεις ωμά δεδομένα, χρειάζεται πολλά χρόνια ιστορικού για να ανακαλύψει μόνο του ότι η
παραγωγή ανεμογεννήτριας αυξάνεται με τον κύβο της ταχύτητας του αέρα. Αν το βάλεις εσύ ως
feature, το μοντέλο ξεκινά από εκεί.

**Feature** είναι μια ποσότητα που βοηθά την πρόβλεψη. Το αποτέλεσμα είναι ένας πίνακας με
μία γραμμή ανά ώρα και μία στήλη ανά feature.

## Ο κανόνας που κυβερνά τα πάντα: το τεστ του gate closure
Για κάθε feature ρώτα: **αν προβλέπω την ώρα h της ημέρας D, ήταν αυτή η τιμή γνωστή στο
κλείσιμο της δημοπρασίας (μεσημέρι D-1);** Αν όχι, δεν επιτρέπεται.

| Feature | Γνωστό στο gate closure; |
|---|---|
| Ώρα, αργία, ημέρα εβδομάδας | Ναι, πάντα |
| Πρόγνωση καιρού για την D | Ναι |
| Πρόβλεψη φορτίου και ΑΠΕ για την D (day-ahead) | Ναι |
| Πραγματική παραγωγή ΑΠΕ της D | Όχι |
| Τιμή της ίδιας ώρας στην D-1 | Ναι (η δημοπρασία της D-1 έχει κλείσει) |
| Τιμή της ώρας 03:00 της D για πρόβλεψη της 15:00 | **Όχι**, κλείνουν μαζί |
| Τιμή γειτονικής ζώνης για την D | Όχι, οι ζώνες κλείνουν ταυτόχρονα |

## Τα μπλοκ features

### 1. Ημερολόγιο
Ώρα, ημέρα εβδομάδας, μήνας, Σαββατοκύριακο, αργίες, «γέφυρες», ώρες αιχμής. Οι κυκλικές
μεταβλητές κωδικοποιούνται με ημίτονο και συνημίτονο, ώστε το 23:00 να είναι κοντά στο
00:00:

```python
ang = 2 * np.pi * hour / 24
df["hour_sin"], df["hour_cos"] = np.sin(ang), np.cos(ang)
```

### 2. Καιρός με φυσική
- **Βαθμοημέρες:** `HDD = max(T_base − T, 0)` και `CDD = max(T − T_base, 0)`. Η ζήτηση δεν
  μεγαλώνει γραμμικά με τη θερμοκρασία, αλλά πάνω από ένα όριο.
- **Καμπύλη ισχύος ανεμογεννήτριας:** 0 κάτω από μια ταχύτητα εκκίνησης (~3 m/s),
  αύξηση ανάλογη με τον κύβο της ταχύτητας μέχρι την ονομαστική (~12 m/s), πλατό και
  μηδέν πάνω από το όριο διακοπής (~25 m/s).
- **Ηλιακή ισχύς:** ακτινοβολία επί συντελεστή απώλειας ~0,4 % ανά °C πάνω από τους 25 °C.
- **Σταθμισμένοι μέσοι:** η θερμοκρασία ζήτησης σταθμίζεται με βάση πού ζει ο πληθυσμός, ο
  άνεμος με βάση πού υπάρχουν ανεμογεννήτριες.

```python
def wind_power_curve(v, cut_in=3, rated=12, cut_out=25):
    cf = pd.Series(0.0, index=v.index)
    ramp = (v >= cut_in) & (v < rated)
    cf[ramp] = (v[ramp]**3 - cut_in**3) / (rated**3 - cut_in**3)
    cf[(v >= rated) & (v < cut_out)] = 1.0
    return cf
```

### 3. Δίκτυο: το residual load
```
residual_load = φορτίο − αιολικά − φωτοβολταϊκά
```
Είναι το feature με τη μεγαλύτερη επίδραση, γιατί δείχνει πόσο ψηλά στο merit order θα
κλείσει η αγορά. Χρησιμοποίησε τις **προβλέψεις** φορτίου και ΑΠΕ και όχι τις πραγματικές
τιμές. Συμπλήρωσε με πραγματικές μόνο όταν λείπει η πρόβλεψη, και μόνο αν είσαι σίγουρος
ότι δεν υπάρχει διαρροή.

### 4. Αυτοπαλινδρόμηση τιμής (η «μνήμη» της αγοράς)
Τιμές με καθυστέρηση 24, 48, 168 ωρών, κυλιόμενοι μέσοι, τυπική απόκλιση (αστάθεια),
skewness (καθεστώς spikes). Τα κυλιόμενα στατιστικά μετατοπίζονται (`.shift(24)`), ώστε να
μην περιέχουν την ημέρα-στόχο:

```python
f["lag_24h"]  = price.shift(24)
f["lag_168h"] = price.shift(168)
f["roll_mean_24h"] = price.rolling(24).mean().shift(24)
f["roll_std_24h"]  = price.rolling(24).std().shift(24)
```

Η ελάχιστη καθυστέρηση 24 ωρών έχει δύο λόγους: αποφεύγει τη διαρροή και κρατά την ίδια
ώρα του κύκλου (μια καθυστέρηση 12 ωρών συγκρίνει νύχτα με μέρα).

### 5. Καύσιμα και κόστος
Το βραχυπρόθεσμο οριακό κόστος (SRMC) ενός σταθμού αερίου:
```
SRMC = (τιμή_αερίου + τιμή_CO₂ × συντελεστής_εκπομπών) / βαθμός_απόδοσης
```
Με τυπικές τιμές: απόδοση ~50 %, συντελεστής ~0,2 tCO₂ ανά MWh θερμικής ενέργειας.
Χρησιμοποίησε το κλείσιμο της **προηγούμενης** εμπορικής ημέρας. Ποτέ μην βάζεις ως input
μεγέθη που περιέχουν την τιμή του ρεύματος (π.χ. spark spread), γιατί είναι έξοδοι.

### 6. Διασυνδέσεις
Οι τιμές των γειτονικών ζωνών και οι διαφορές τους από την τοπική, με καθυστέρηση (D-1,
D-7), γιατί οι συζευγμένες αγορές κλείνουν ταυτόχρονα. Η φθηνότερη γειτονική τιμή λειτουργεί
σαν «ταβάνι» στην τοπική.

## Συναρμολόγηση του πίνακα
Κάθε μπλοκ επιστρέφει DataFrame με ωριαίο index. Ο ενορχηστρωτής φτιάχνει τον κοινό άξονα
χρόνου, κάνει `reindex` σε κάθε μπλοκ και τα ενώνει με `pd.concat(axis=1)`. Μπλοκ χωρίς
δεδομένα παραλείπεται. Μια **αναφορά ποιότητας** (ποσοστό μη κενών, min/μέσος/max ανά
feature) πιάνει εύκολα προβλήματα.

## Συχνά λάθη
- Διαρροή μέσα από κυλιόμενα στατιστικά χωρίς `shift`.
- Ένα feature που δουλεύει εντυπωσιακά καλά και κανείς δεν ξέρει γιατί: έλεγξέ το για
  διαρροή.
- Υπερβολικά πολλά συσχετισμένα features χωρίς φυσικό νόημα.
- Άλλαξε ένα feature και ξέχασες τα παράγωγά του (βλ. Κεφ. 7, ανάλυση σεναρίων).
