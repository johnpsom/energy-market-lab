# Κεφάλαιο 7: Εξήγηση, γιατί προβλέπεται αυτή η τιμή

## Το πρόβλημα
Μια πρόβλεψη χωρίς εξήγηση δεν εμπνέει εμπιστοσύνη. Ο αναλυτής ρωτά «γιατί 140 €/MWh;»
και θέλει απάντηση στη γλώσσα της αγοράς: «Χαμηλός αέρας και υψηλό φορτίο ανεβάζουν το
residual load». Η εξήγηση βοηθά και εσένα: αν το μοντέλο στηρίζεται σε λάθος λόγο, το
βλέπεις πριν σε κοστίσει.

## SHAP: κατανομή της πρόβλεψης στα features
Οι τιμές SHAP μοιράζουν τη διαφορά ανάμεσα στην πρόβλεψη και τη μέση πρόβλεψη σε
συνεισφορές ανά feature. Κάθε συνεισφορά είναι σε μονάδες του στόχου (€/MWh) και οι
συνεισφορές αθροίζουν στην πρόβλεψη. Το LightGBM τις δίνει απευθείας:

```python
contrib = booster.predict(X_day, pred_contrib=True)   # (ώρες, features + 1)
mean_contrib = contrib[:, :-1].mean(axis=0)           # μέση συνεισφορά της ημέρας
top = np.argsort(np.abs(mean_contrib))[::-1][:5]      # οι 5 κυριότεροι
```

Η τελευταία στήλη είναι η βασική τιμή (base value) και την παραλείπεις. Ο μέσος όρος πάνω
στις ώρες της ημέρας δίνει «οι κυριότεροι παράγοντες της ημέρας». Μπορείς να τον
υπολογίσεις και ανά ώρα, για να δεις ποιος παράγοντας κορυφώνεται πότε.

## Από ονόματα στηλών σε ανθρώπινη γλώσσα
Φτιάξε έναν πίνακα αντιστοίχισης:

| Feature | Ετικέτα |
|---|---|
| `residual_load` | φορτίο μετά τις ΑΠΕ |
| `wind_power_proxy` | αιολική παραγωγή |
| `price_lag_24h` | χθεσινή τιμή την ίδια ώρα |
| `cdd` | ζήτηση ψύξης |

Και πρότυπο πρότασης: «Η μέση τιμή της ημέρας ανεβαίνει κατά ~Χ €/MWh λόγω [ετικέτα], ενώ
μειώνεται κατά ~Ψ €/MWh λόγω [ετικέτα]».

## Ανάλυση σεναρίων (what-if)
«Τι θα γινόταν αν ο αέρας ήταν 30 % χαμηλότερος;» Αλλάζεις τα σχετικά features και
ξαναϋπολογίζεις την πρόβλεψη.

```python
base = predict(X)["p50"].mean()
X_shock = X.copy()
X_shock["wind_power_proxy"] *= 0.7
shocked = predict(X_shock)["p50"].mean()
delta = shocked - base
```

**Προσοχή στη συνέπεια των παράγωγων features.** Αν μειώσεις την αιολική παραγωγή αλλά
αφήσεις αμετάβλητο το residual load, που προκύπτει από αυτήν, το σενάριο είναι
αντιφατικό και υποτιμά την επίδραση. Σε ένα σωστό σενάριο ξαναϋπολογίζεις όλα τα features
που εξαρτώνται από το μέγεθος που άλλαξες (residual load, ποσοστό ΑΠΕ, κ.λπ.).

## Περιορισμοί της εξήγησης

- **Συσχέτιση, όχι αιτιότητα.** Το SHAP λέει τι χρησιμοποίησε το μοντέλο και όχι τι
  προκαλεί την τιμή στον πραγματικό κόσμο.
- **Συσχετισμένα features.** Όταν δύο features κινούνται μαζί (αέρας και ποσοστό ΑΠΕ), η
  συνεισφορά μοιράζεται μεταξύ τους κατά αυθαίρετο τρόπο. Διάβασε τις ομάδες features μαζί.
- **Η εξήγηση είναι τόσο καλή όσο το μοντέλο.** Αν το μοντέλο έχει μάθει ψευδή σχέση λόγω
  διαρροής, η εξήγηση θα την παρουσιάσει πειστικά.

## Το «πρωινό δελτίο»
Μια χρήσιμη μορφή εξόδου για τον τελικό χρήστη:

1. Η ημέρα που προβλέπεται και η μέση τιμή.
2. Οι ώρες της φθηνότερης και της ακριβότερης τιμής, με διάστημα P10–P90.
3. Πιθανότητα spike και αρνητικής τιμής.
4. Οι τρεις έως πέντε κυριότεροι παράγοντες, με τη φορά τους (ανεβάζει/κατεβάζει).
5. Μία ανάλυση σεναρίου (π.χ. «χωρίς αέρα»).
6. Σαφής ένδειξη του πόσο έχει αποδώσει ο έλεγχος τις τελευταίες εβδομάδες.

## Συχνά λάθη
- Παρουσίαση SHAP χωρίς μετάφραση στα ονόματα της αγοράς.
- Σενάρια που αλλάζουν ένα feature και αφήνουν τα παράγωγά του.
- Ερμηνεία των παραγόντων ως αιτιακών.
