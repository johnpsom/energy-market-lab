# Κεφάλαιο 8: Λειτουργία και dashboard

## Το πρόβλημα
Ένα μοντέλο που δουλεύει στο notebook δεν είναι σύστημα. Για να έχει αξία, πρέπει να τρέχει
κάθε μέρα χωρίς παρέμβαση, να ενημερώνεται όταν έρχονται νέα δεδομένα, να δείχνει τα
αποτελέσματα και να σε προειδοποιεί όταν χαλάσει.

## Η ημερήσια ακολουθία

```
1. Συλλογή        τελευταίες τιμές, φορτίο, παραγωγή, καιρός, καύσιμα
2. Αποθήκευση     upsert (idempotent)
3. Features       ξαναχτίσιμο του πίνακα
4. Εκπαίδευση     (κυλιόμενο παράθυρο, βαθμονόμηση)
5. Πρόβλεψη       για την επόμενη ημέρα και, αν χρειάζεται, για επόμενες
6. Πάγωμα         αποθήκευση των προβλέψεων με την ώρα έκδοσης
7. Έλεγχος        βαθμολόγηση των χθεσινών προβλέψεων με τις πραγματικές τιμές
```

Ο συγχρονισμός έχει σημασία. Οι τιμές της αυριανής ημέρας δημοσιεύονται λίγο μετά το
μεσημεριανό κλείσιμο της δημοπρασίας. Η πρόβλεψη που γίνεται *πριν* το κλείσιμο είναι η
χρήσιμη. Αν το σύστημα τρέξει μετά, η «πρόβλεψη» είναι ήδη γνωστό αποτέλεσμα.

## Αρχές αξιόπιστης λειτουργίας

### Idempotency
Κάθε βήμα πρέπει να μπορεί να τρέξει ξανά με ασφάλεια (Κεφ. 3). Όταν κάτι αποτύχει στη μέση,
ξανατρέχεις όλη την ακολουθία.

### Ένα εκτελέσιμο ανά εργασία
Φτιάξε μικρά scripts: `pull_data`, `build_features`, `train`, `forecast`, `verify`. Η
λογική ζει σε modules και τα scripts είναι απλά «κουμπιά». Έτσι τα ίδια modules καλούνται από
τον προγραμματιστή εργασιών, από tests και από το dashboard.

### Προγραμματισμός
Χρησιμοποίησε αυτό που έχει η πλατφόρμα σου: cron στο Linux, Task Scheduler στα Windows,
ή ένα σύστημα ροής εργασιών όπως το Airflow όταν μεγαλώσει το σύστημα. Σημαντικό:
**αρχείο καταγραφής (log)** ανά εκτέλεση, με ώρα και κωδικό εξόδου.

### Διαφορετικές συχνότητες για διαφορετικά βάρη
- **Ημερήσια:** ανανέωση δεδομένων και εκπαίδευση της παραγωγικής έκδοσης.
- **Εβδομαδιαία:** walk-forward έλεγχος, που είναι βαρύς γιατί ξαναεκπαιδεύει δεκάδες φορές.

### Ορίζοντας πρόβλεψης
Η επίσημη πρόβλεψη καλύπτει την επόμενη ημέρα. Για μεγαλύτερο ορίζοντα (π.χ. 6–7 ημέρες)
οι είσοδοι είναι πιο αβέβαιες: δεν υπάρχουν δημοσιευμένες προβλέψεις φορτίου και ΑΠΕ, οπότε
προσεγγίζονται από τον καιρό και την κλιματολογία. Δείξε τον μεγαλύτερο ορίζοντα ως
«προοπτική» (outlook) με σαφή προειδοποίηση για τη μειωμένη ακρίβεια.

## Παρακολούθηση (monitoring)
Ένα σύστημα που δεν παρακολουθείται θα χαλάσει σιωπηλά. Έλεγχοι που αξίζουν:

| Έλεγχος | Τι πιάνει |
|---|---|
| Φρεσκάδα δεδομένων (πότε ήρθε η τελευταία γραμμή) | Σταμάτημα πηγής ή αλλαγή API |
| Πλήθος γραμμών ανά ημέρα (23/24/25 ώρες) | Κενά ή διπλότυπα |
| Κυλιόμενη κάλυψη διαστημάτων | Επιδείνωση βαθμονόμησης |
| Κυλιόμενο MAE και skill | Αλλαγή καθεστώτος αγοράς (drift) |
| Κατανομή των features | Άλλαξε το σχήμα ή οι μονάδες μιας πηγής |

Όταν η ποιότητα πέφτει, η αντίδραση είναι συνήθως επανεκπαίδευση σε πιο πρόσφατο παράθυρο.
Αν δεν αρκεί, ξαναδές τα features.

## Το dashboard
Ο τελικός χρήστης χρειάζεται λίγες οθόνες:

1. **Πρόβλεψη της ημέρας:** ωριαία καμπύλη P50 με σκιασμένο διάστημα P10–P90 και
   ένδειξη spike.
2. **Προοπτική:** οι επόμενες ημέρες.
3. **Εξήγηση:** κυριότεροι παράγοντες και σενάριο.
4. **Επαλήθευση:** τα αποτελέσματα της περιόδου (MAE, κάλυψη, skill) και η ημέρα-ημέρα
   πορεία. Η οθόνη αυτή χτίζει εμπιστοσύνη, γιατί δείχνει και τα λάθη.

Μια λεπτή υλοποίηση με ένα μικρό web framework (π.χ. FastAPI) και βιβλιοθήκη γραφημάτων
(Plotly) αρκεί:

```python
@app.get("/api/brief")
def brief(date: str | None = None): ...

@app.get("/api/outlook")
def outlook(days: int = 7): ...

@app.get("/api/verification")
def verification(): ...
```

**Cache** τα βαριά αποτελέσματα με κλειδί την ημερομηνία, ώστε το dashboard να μην
ξαναϋπολογίζει σε κάθε φόρτωση.

## Ασφάλεια και διαχείριση μυστικών
Tokens και κωδικοί μένουν σε αρχείο περιβάλλοντος, εκτός version control, και ποτέ στον
κώδικα ή στα logs. Δώσε στο dashboard μόνο ανάγνωση της αποθήκης.

## Συχνά λάθη
- Χειροκίνητη εκτέλεση χωρίς αρχείο καταγραφής.
- Αυτόματη εκτέλεση χωρίς ειδοποίηση σε αποτυχία.
- Επανεκπαίδευση που αντικαθιστά το παλιό μοντέλο χωρίς να κρατά αντίγραφο.
- Dashboard που δείχνει μόνο επιτυχίες.

## Άσκηση
Στήσε ένα script που τρέχει τα βήματα 1–3 και γράφει σε αρχείο log την ώρα και τον αριθμό
των νέων γραμμών. Προγραμμάτισέ το να τρέχει κάθε πρωί και έλεγξε το log της επομένης.
